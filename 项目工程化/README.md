# 全通劳务 AI 招工助手｜企业开发流程包

本目录把项目从产品构思到上线运维整理成一套可执行的工程流程。当前产品方向是“甲方项目级数据主权与审计载体”，RAG、岗位匹配和流程页面是留客工具。文档以当前 `labor-ai-demo` MVP 为基线，未把尚未验证的目标指标写成既成事实。

## 使用方式

1. 产品或业务变更先更新 `01-产品管理`。
2. 进入迭代前，在 `02-项目管理/迭代计划.md` 登记范围、负责人和完成标准。
3. 开发和架构变更同步记录到 `04-技术架构`、`05-开发实施`。
4. 合并前执行 `06-测试质量/发布前检查清单.md`。
5. 上线执行 `07-发布上线` 和 `08-部署运维`，上线后补 `09-复盘运营`。

## 生命周期

```text
需求发现 → PRD评审 → 交互确认 → 技术评审 → 迭代开发 → 测试验收
    → 发布评审 → 部署上线 → 监控运营 → 复盘改进
```

## 当前基线

- 入口：`app.py`
- AI服务：`ai_service.py`
- 知识库：`knowledge_base.py`
- 会话持久化：`conversation_store.py`
- 数据：`data/jobs.json`、`data/faq.md`、SQLite、Chroma
- 运行：Streamlit + Ollama + qwen2.5
- 已完成：RAG问答、来源追溯、多轮上下文、岗位筛选、候选人匹配、报名状态、会话记录、首屏改版
- 已实现/待验证：向量 + 本地词法混合检索与 RRF
- 未承诺：项目级权限、不可篡改审计、甲方看板、密钥自控、重排序、RAGAS分数、语义缓存、公网生产部署

## 变更控制

任何影响用户行为、数据结构、模型、依赖或部署方式的变更，都要同时更新对应阶段文档，并在发布说明中记录版本、风险和回滚方式。
