# 07｜发布上线

本目录定义全通劳务 AI 招工助手从“可合并”到“可上线”的发布门禁、版本记录和回滚方法。

## 当前边界

- 本项目当前基线是 Streamlit + Ollama + Chroma + SQLite 的 MVP。
- Windows 本地启动路径已有验证；云端文档是可执行 Runbook，但本目录不代表已经完成真实云端部署。
- 没有把模型质量、并发量或公网可用性写成承诺。上线前必须用本次发布版本重新验收。

## 文件地图

| 文件 | 用途 |
|---|---|
| `发布流程.md` | 角色、阶段门禁、版本和发布操作 |
| `发布前检查清单.md` | 每次发布逐项勾选并留存证据 |
| `CHANGELOG.md` | 面向用户和运维的变更记录模板 |
| `回滚方案.md` | 代码、配置、数据和模型异常时的回退步骤 |

## 最小发布闭环

```text
需求/缺陷 → 变更评审 → 开发分支 → 自动/本地测试 → 发布候选
→ 验收与备份 → 小流量发布 → 观察窗口 → 完成/回滚 → 记录
```

## 发布原则

1. 每次发布必须绑定 Git 提交 SHA、版本号、变更说明、验收证据和回滚点。
2. 先备份 `data/`（尤其是 `data/labor_ai.db`），再替换应用文件或依赖。
3. 密码、令牌、`.env`、虚拟环境、`chroma_db/` 和运行日志不得打入发布包。
4. 数据结构、模型、依赖或检索策略变化必须在发布说明中单独标注风险。
5. 任何无法在观察窗口内解释的错误率、响应延迟或数据异常，都优先回滚到最近稳定版本。
