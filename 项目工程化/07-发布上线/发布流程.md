# 发布流程

## 1. 角色与职责

| 角色 | 责任 | 最低授权 |
|---|---|---|
| 产品负责人 | 确认范围、验收标准、用户影响 | 发布/不发布 |
| 开发负责人 | 代码、依赖、迁移和回滚步骤 | 技术签字 |
| 测试/验收人 | 执行回归、冒烟和证据留存 | 质量签字 |
| 发布负责人 | 执行部署、观察窗口、记录结果 | 变更执行 |
| 值班/运维 | 监控、事故升级、恢复服务 | 生产操作 |

小团队可以由同一人兼任多个角色，但“开发”和“发布验收”仍应有第二人复核，或由产品负责人确认。

## 2. 阶段门禁

### Gate A：范围冻结

- `01-产品管理` 中的需求、验收标准和不做范围已更新。
- 变更拥有负责人、目标版本和风险等级。
- 数据、隐私、模型和部署影响已标记。

### Gate B：开发完成

- 分支已合并或已生成候选提交，工作区无未解释的改动。
- Python 语法检查、自动化测试和手工冒烟通过。
- `requirements.txt`、环境变量说明和文档与代码一致。

### Gate C：发布候选（RC）

在项目目录执行（PowerShell）：

```powershell
Set-Location D:\1-myFiles\Desktop\AI实习\labor-ai-demo
git status --short
git rev-parse --short HEAD
python -m py_compile app.py ai_service.py knowledge_base.py conversation_store.py
python -m pytest -q
```

若本机未安装测试依赖，必须在发布记录中写明“未执行”和原因，不得将其写成通过。

需要 Ollama 的验收在已配置的运行环境中执行：

```powershell
python check_environment.py --build-index
streamlit run app.py --server.headless true --server.port 8501
```

另开终端访问 `http://localhost:8501`，完成至少 5 个岗位/FAQ 问题、一次多轮追问和一次错误输入测试。

### Gate D：发布评审

发布负责人核对 `发布前检查清单.md`，确认：

- 版本号、Git SHA 和发布包校验值已记录。
- 线上（或演示环境）备份已完成并可读。
- 回滚命令在当前环境可用。
- 负责人、观察窗口和升级联系人已明确。

### Gate E：发布与观察

1. 在低流量窗口执行部署。
2. 先做健康检查和关键路径冒烟，再开放给用户。
3. 观察至少 30 分钟（首次公网发布建议 60 分钟）。
4. 记录错误、延迟、模型可用性、磁盘和用户反馈。
5. 达到回滚条件立即停止继续发布并执行 `回滚方案.md`。

## 3. 版本和分支约定

- 使用 SemVer：`MAJOR.MINOR.PATCH`。
  - `MAJOR`：不兼容的接口、数据或部署变化。
  - `MINOR`：向后兼容的功能或数据能力。
  - `PATCH`：兼容的缺陷、安全或文案修复。
- 功能开发使用短生命周期分支；发布候选可使用 `release/vX.Y.Z`，紧急修复使用 `hotfix/vX.Y.Z`。
- 标签格式：`vX.Y.Z`，标签必须指向经过验收的提交。
- 未完成内容放入 `Unreleased`，不得把计划功能写进已发布版本。

## 4. 发布记录（复制到迭代记录）

| 字段 | 内容 |
|---|---|
| 版本 | `vX.Y.Z` |
| Git SHA | `待填写` |
| 发布类型 | 功能 / 修复 / 安全 / 紧急 |
| 负责人 | `待填写` |
| 计划时间 | `YYYY-MM-DD HH:mm` |
| 观察结束 | `YYYY-MM-DD HH:mm` |
| 变更摘要 | `待填写` |
| 数据/模型变化 | 无 / 说明 |
| 备份位置与校验值 | `待填写` |
| 验收证据 | 截图、日志、测试报告链接 |
| 结果 | 成功 / 回滚 / 部分成功 |

## 5. 紧急发布

仅用于安全漏洞、服务完全不可用或数据损坏风险。发布负责人先在工单/群组中写明“影响、原因假设、回滚点和授权人”，完成最小测试后发布；事后 24 小时内补齐完整 `CHANGELOG` 和复盘记录。
