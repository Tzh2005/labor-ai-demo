# PRD｜全通劳务甲方数据主权工作台

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品负责人 | 全通劳务业务负责人 |
| 技术负责人 | AI应用开发负责人 |
| 版本 | 1.1 数据主权方向 |
| 用户 | 甲方项目负责人、甲方审计/法务、劳务运营人员、求职工人 |
| 核心目标 | 为每个甲方项目提供专属、可审计、可导出的用工数据与流程载体；RAG 是可信检索入口 |

## 2. 用户痛点

- 工资、地点、住宿、班次和入职要求分散在岗位资料中。
- 客服重复回答同类问题，难以保持口径一致。
- 用户常用口语追问，传统关键词搜索无法理解上下文。
- AI回答必须能回到岗位或FAQ来源，不能凭空承诺。
- 甲方需要知道自己的项目数据在哪里、谁访问过、谁修改过，并能在纠纷或迁移时导出证据。

## 3. 产品目标

### 当前 MVP 目标

1. 支持自然语言查询岗位和FAQ。
2. 支持最近对话上下文和追问。
3. 展示回答参考来源。
4. 支持按工作地区、岗位类型浏览岗位。
5. 本地运行，不依赖外部模型API。

### V1 数据主权目标

1. 每条业务记录带 `project_id`，默认只返回当前项目数据。
2. 建立甲方成员、角色和最小权限模型。
3. 对查看、导出、修改、审批和同步建立不可篡改审计事件。
4. 提供甲方项目看板和标准化数据/证据包导出。
5. 敏感字段加密保存，密钥与业务数据分离管理。

### 非目标

- 不在当前 MVP 中处理签约、工资结算或真实个人敏感档案；报名仅用于脱敏演示流程。
- 不把模拟岗位数据包装成真实招聘承诺。
- 不在未完成安全评审前接入微信、短信或支付渠道。

## 4. 核心流程

```text
用户输入问题 → 判断问题类型 → 检索岗位/FAQ → 生成带来源回答
     ↓                         ↘ 无可靠资料
浏览岗位 ← 筛选地区/岗位类型 ← 明确提示转人工核实
```

## 5. 功能范围

| 模块 | MVP | 后续 |
|---|---|---|
| 智能问答 | 自然语言、上下文、来源 | 意图路由、问题改写 |
| 岗位浏览 | 列表、地区/岗位筛选 | 收藏、状态、推荐 |
| 知识库 | Chroma向量检索、增量索引 | BM25混合检索、重排序 |
| 运营 | SQLite会话记录、响应耗时 | 检索耗时、缓存命中、满意度 |
| 项目主权 | 当前单项目演示 | 项目隔离、权限、审计、甲方看板、导出 |
| 管理 | 环境状态提示 | 岗位后台、审核、密钥和同步策略 |

## 6. 验收标准

- 用户输入“石岩附近有什么普工岗位”时，返回岗位库中存在的岗位，并显示来源。
- 用户追问“工资多少”时，能结合上一轮岗位上下文回答。
- 用户切换地区和岗位类型后，列表只显示符合条件的岗位。
- Ollama不可用时，页面给出可操作提示，不展示堆栈信息。
- 每次回答可记录会话ID、角色、内容和来源。
- 对不存在的信息明确说明“需要人工确认”，不编造工资或福利。

## 7. 产品指标

上线前只记录可验证指标：

- 检索命中率、来源覆盖率、回答事实性：由评估集测量。
- 首字延迟、全文延迟、P95延迟：由监控日志测量。
- 无来源回答率、错误率、人工转接率：由运营数据测量。
