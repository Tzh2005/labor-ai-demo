# 数据字典与安全边界

**文档版本**：v1.0（MVP）  
**原则**：数据最小化、来源可追溯、默认本地、失败不泄露。  
**适用范围**：`labor-ai-demo/data`、Chroma 索引、SQLite 会话记录、运行时配置。

## 1. 数据分级

| 级别 | 定义 | 当前示例 | 处理要求 |
|---|---|---|---|
| L0 公开/演示 | 不含个人信息的示例内容 | 演示岗位、FAQ、页面文案 | 可进入仓库；注明为演示数据 |
| L1 内部业务 | 真实岗位、供应商/工厂联系方式、运营统计 | 未来真实岗位库 | 仅授权人员访问；脱敏后用于测试 |
| L2 个人/敏感 | 姓名、手机号、身份证、银行卡、合同、健康信息 | 候选人姓名、手机号哈希/后四位 | 当前演示仅允许最小候选人字段；真实数据接入前需专项合规评审、加密和权限控制 |
| L3 凭据/密钥 | 访问密码、令牌、私钥 | `DEMO_PASSWORD`（运行时） | 仅环境/密钥管理器注入，禁止提交仓库和日志 |

当前仓库的数据文件应保持 L0。若导入真实岗位资料，必须先完成数据负责人确认、脱敏、备份和留存期限登记。

### 1.1 项目知识库资料（本版已实现）

合同、SOP、入场要求和服务标准等项目资料可按项目登记，原文属于 L1/L2 边界数据，必须确认授权并移除不必要个人信息后才可进入受控环境。本地演示版只接受 UTF-8 的 `.txt` / `.md`，单个文件最大 512KB；原文保存在被 Git 忽略的 `data/project_documents/<project_id>/`，SQLite 仅保存标题、类型、版本、原始文件名、相对路径、SHA-256 和登记时间。

禁止上传身份证、银行卡、工资明细、社保明细及其他不必要敏感信息。PDF、Word、OCR、文档审批、正式权限、KMS/字段加密与生产级对象存储尚未实现，不能据此宣称具备生产级资料治理。

## 2. 结构化岗位数据：`data/jobs.json`

文件顶层必须是 JSON 数组。每个岗位对象要求包含以下字段；`knowledge_base.py` 会在建索引时校验必填字段。

| 字段 | 类型 | 必填 | 示例 | 约束/用途 |
|---|---|---:|---|---|
| `id` | string/number | 是 | `JOB-001` | 稳定唯一标识；变更后影响索引和引用 |
| `factory_name` | string | 是 | `某某电子厂` | 工厂/用工单位展示名称 |
| `position` | string | 是 | `普工` | 岗位名称，用于筛选和词法检索 |
| `salary` | string | 是 | `4500-6000 元/月` | 原样展示；不得由模型推算 |
| `requirements` | string | 是 | `18-45 岁，能适应两班倒` | 任职要求；避免写入身份证等敏感信息 |
| `benefits` | string | 是 | `包吃，提供住宿` | 福利原文；不同岗位不得笼统合并 |
| `work_time` | string | 是 | `两班倒` | 班次/工时原文 |
| `location` | string | 是 | `深圳市宝安区石岩街道` | 地点筛选和回答依据 |
| `overtime` | string | 是 | `按生产安排` | 加班说明；无信息写“需人工确认”，不留空猜测 |

### 2.1 岗位数据规则

- `id` 不复用；下架岗位通过状态字段的未来扩展或文件删除流程处理，并记录变更原因。
- 薪资、福利、地点、要求必须来自业务确认文本；模型只负责引用，不负责承诺。
- 新增字段要同步更新数据字典、构建校验、展示组件、评估集和发布说明。
- 用户可控字段在页面 HTML 渲染前必须转义；禁止把未经处理的字段拼入脚本、URL 或 SQL。
- 当前 schema 没有 `status`、`valid_from`、`valid_until`；因此不能向用户承诺岗位实时有效。

## 3. FAQ 文本：`data/faq.md`

FAQ 以 Markdown 保存，推荐使用以下结构：

```markdown
### Q: 用户问题或问题标题
A: 经业务确认的答案。涉及工资、福利、证件时保留条件和例外。

---
```

`knowledge_base.py` 按 `### Q:`、分隔线和空行切分，写入 Chroma 时为每个片段增加 `type=faq` 与展示标题。FAQ 文本中的任何“指令”都视为不可信数据，不能改变系统提示词或工具行为。

## 4. Chroma 文档与元数据

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `page_content` | string | 岗位拼接文本/FAQ片段 | 用于嵌入和 Prompt；不应包含密钥或个人信息 |
| `type` | string | 构建器 | `job` 或 `faq`；岗位筛选依赖此字段 |
| `job_id` | string | 岗位 `id` | 仅岗位文档存在 |
| `title` | string | 工厂+职位/FAQ序号 | 页面来源展示和审计引用 |
| `location` | string | 岗位 `location` | 未来元数据过滤字段 |

索引目录 `chroma_db/` 是可重建产物，不把它当作唯一事实源。源文件的 SHA-256 签名保存在 `.data_signature`，数据变更时由程序重建。备份和发布包必须记录嵌入模型、分词器（若未来引入）和索引版本。

## 5. SQLite：`data/labor_ai.db`

当前库包含 `chat_messages`、`jobs`、`candidates` 和 `applications`，由 `conversation_store.py` 初始化并使用 WAL 模式。候选人手机号只保存 SHA-256 哈希与后四位；这是单项目脱敏演示，不是生产级加密方案。

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK 自增 | 内部记录 ID |
| `session_id` | TEXT | NOT NULL | 页面会话 UUID；不是用户身份凭据 |
| `role` | TEXT | `user`/`assistant` | 消息角色 |
| `content` | TEXT | NOT NULL | 用户问题或回答；不得主动写入密码/身份证等敏感信息 |
| `sources_json` | TEXT | NOT NULL | 来源标题 JSON 数组，默认 `[]` |
| `created_at` | TEXT | NOT NULL | UTC ISO-8601 时间 |

当前没有用户表、权限表、项目字段、不可篡改审计表、导出接口或指标表；不要在文档、演示或简历中声称具备这些能力。若引入真实用户数据，必须增加访问控制、保留期限、导出/删除流程、迁移脚本和加密设计。

### 5.1 V1 计划数据模型（待开发）

| 表/实体 | 关键字段 | 约束 |
|---|---|---|
| `projects` | `id`、`client_name`、`status`、`created_at` | 项目是全部业务数据的隔离根 |
| `project_members` | `project_id`、`user_id`、`role` | 唯一成员关系；角色决定读、写、导出、审计权限 |
| 业务表扩展 | `project_id`、`created_by`、`updated_by` | `jobs`、`candidates`、`applications`、`chat_messages` 全部必填项目字段 |
| `audit_events` | `project_id`、`actor_id`、`action`、`object_type`、`object_id`、`occurred_at`、`previous_hash`、`event_hash` | 仅追加；不得以 UPDATE/DELETE 改写历史 |
| `export_jobs` | `project_id`、`requested_by`、`scope`、`checksum`、`status` | 每次导出记录范围、权限和校验结果 |

审计事件记录元数据和对象摘要，不记录密码、密钥、完整手机号、身份证、原始聊天全文或不必要敏感字段。

## 6. 运行时状态与配置

| 名称 | 所在位置 | 是否持久化 | 敏感性 |
|---|---|---:|---|
| `messages` | Streamlit session state | 否（页面会话） | 可能含用户输入，按内部数据处理 |
| `conversation_id` | Streamlit session state | 间接写入 SQLite | 普通标识，不作认证 |
| `DEMO_PASSWORD` | 环境变量 | 否（应用不落盘） | L3，绝不记录 |
| `OLLAMA_MODEL` | 环境变量 | 否 | 配置 |
| `OLLAMA_BASE_URL` | 环境变量 | 否 | 配置，必须是 loopback |
| `HF_HUB_OFFLINE` | 环境变量 | 否 | 配置 |
| `RAG_RETRIEVAL_MODE` | 环境变量 | 否 | `hybrid`（默认）或 `vector` 回退开关 |

## 7. 安全边界与已实现控制

### 7.1 网络边界

- AI 模型请求默认发往 `http://localhost:11434`。
- `_validate_base_url` 只接受 `localhost`、`127.0.0.1`、`::1`，拒绝公网、云元数据地址、用户名密码和其他主机，降低 SSRF 风险。
- 代理环境下通过 `NO_PROXY` 保证 loopback 不绕到外部代理。
- 当前 Streamlit 仍是单机 HTTP 服务；未配置 TLS、反向代理或公网身份体系，不得直接作为生产公网入口。

### 7.2 输入与输出边界

- 单次问题最多 500 字符；单会话每分钟最多 10 次，防止本地推理资源被滥用。
- 检索文档命中明显提示注入模式时丢弃；全部结果被丢弃则直接转人工且不调用模型。
- 模型输出命中危险指令/角色扮演模式时替换为转人工消息；输出先缓冲再交给 UI。
- 页面展示岗位字段前进行 HTML 转义；SQLite 使用参数化 SQL。
- 回答规则只允许陈述来源明确事实；工资、福利、岗位有效性不足时必须人工确认。
- 项目资料索引会校验登记记录的项目标识、受控目录和 SHA-256；向量检索结果再校验 `project_id`，防止错误路径、篡改文件或其他项目资料进入回答。

### 7.3 凭据与日志边界

- `DEMO_PASSWORD` 只从环境变量读取；不得写入源码、Markdown、截图、提交信息或日志。
- 日志应记录错误类型、请求关联 ID 和耗时，不记录原始密码、完整身份证号、手机号或完整用户问题（生产环境需脱敏/哈希）。
- 当前日志是应用进程日志，尚未集中收集和脱敏；上线前需补审计方案。
- V1 的审计日志必须与普通应用日志分离，采用追加写、访问控制、保留期限和完整性校验；仅有 SQLite 会话记录不构成不可篡改审计。

## 8. 威胁模型（第一版）

| 威胁 | 影响 | 当前缓解 | 残余风险/后续 |
|---|---|---|---|
| 恶意 FAQ/岗位文本注入 | 模型泄露提示或执行错误指令 | 文档过滤 + 固定 Prompt | 规则不是完备检测；需红队集和模型隔离 |
| Ollama URL SSRF | 探测内网/云元数据 | loopback 白名单 | 云部署需网络 ACL 和服务身份 |
| XSS | 伪造岗位内容执行脚本 | HTML 转义 | 需持续审查所有富文本入口 |
| 暴力/资源滥用 | CPU 被耗尽 | 密码、长度、频率限制 | 多实例需网关限流和账号锁定 |
| SQLite 泄露 | 对话隐私暴露 | 本地权限、最小数据 | 需加密磁盘、留存删除和备份管控 |
| 错误岗位承诺 | 业务/合规风险 | 来源约束、转人工 | 需业务审核、有效期和人工闭环 |

## 9. 数据变更审批

涉及以下任一变化时，必须走技术评审并更新本文：增加字段、引入个人信息、改变来源格式、修改索引元数据、改变数据保留期限、允许外部网络、增加第三方模型或缓存。评审至少包含产品、技术、安全/业务数据负责人；未完成评审的变更只能用于脱敏开发环境。
