# 08｜部署运维

本目录覆盖应用运行、环境配置、监控、备份和事故响应。它服务于当前 Streamlit + 本地 Ollama MVP，而非通用高并发生产平台设计。

## 当前状态

| 环境 | 状态 | 说明 |
|---|---|---|
| Windows 本地 | 可按 Runbook 验证 | 使用 Python、Ollama、Streamlit 和本地数据目录 |
| Ubuntu 云端 | 待执行 | 仅提供经过审阅的部署模板，不表示已创建实例或开放公网 |
| 公网生产 | 未承诺 | 上线前需补 HTTPS、域名、访问控制、备份演练和容量压测 |

## 文件地图

| 文件 | 用途 |
|---|---|
| `部署Runbook.md` | 本地和 Ubuntu 环境的安装、启动、升级、验证与排障 |
| `监控告警与备份.md` | 健康检查、日志、指标、告警、备份和恢复演练 |
| `事故响应手册.md` | 分级、指挥、沟通、排障和证据保全 |

## 运行资产

| 路径/配置 | 作用 | 处理原则 |
|---|---|---|
| `app.py` | Streamlit 入口 | 随发布版本管理 |
| `ai_service.py`、`knowledge_base.py` | RAG 与 Ollama 调用 | 随发布版本管理 |
| `data/jobs.json`、`data/faq.md` | 岗位和 FAQ 事实源 | 备份、审核、可追溯 |
| `data/labor_ai.db` | 本地会话审计 SQLite | 备份、权限限制、按留存策略处理 |
| `chroma_db/` | 可重建向量索引 | 不作为唯一数据副本 |
| `DEMO_PASSWORD` | 页面认证密码 | 仅由安全环境变量/受限文件注入 |
| `OLLAMA_MODEL` | 对话模型名 | 记录在发布与运维台账 |
| `OLLAMA_BASE_URL` | Ollama 地址 | 当前代码仅允许回环地址 |

## 运维原则

1. 先验证、后开放；先备份、后升级；先隔离、后调查。
2. 应用、数据、配置、模型和日志分开管理，避免发布包覆盖业务数据。
3. 对用户问题、会话内容和密码按最小必要原则访问，日志中不写入敏感值。
4. 所有生产操作应记录操作者、时间、版本、命令意图和结果。
