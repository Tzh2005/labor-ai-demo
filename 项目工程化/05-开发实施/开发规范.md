# 开发规范

**版本**：v1.0  
**适用代码**：`labor-ai-demo` Python、Streamlit、LangChain、测试与脚本。  
**原则**：小步提交、可回滚、先验证边界再扩展能力。

## 1. 开发前置

1. 从 `01-产品管理` 的用户故事或缺陷单建立任务，写清范围、非目标和验收证据。
2. 阅读 `04-技术架构` 中相关边界；涉及数据、模型、网络或依赖时先做技术评审。
3. 在本地创建虚拟环境，使用 `requirements.txt` 安装依赖；不要把模型文件、`venv/`、数据库和 Chroma 产物提交到仓库。
4. 先补失败路径和测试，再实现主流程；任何新配置都要同步环境配置说明。

## 2. Python 与模块规范

- 使用 Python 3.10+，推荐 3.11/3.12；新增代码使用类型标注、短函数和明确返回值。
- 遵循 PEP 8，导入按标准库、第三方、本地模块分组；禁止通配符导入。
- 类/函数命名使用 `PascalCase`/`snake_case`，常量使用 `UPPER_SNAKE_CASE`；布尔变量用 `is_`、`has_`、`should_` 等可读前缀。
- 公共类、函数和环境变量必须有简洁 docstring；注释解释“为什么”，不重复代码表面含义。
- 文件路径使用 `pathlib.Path`；文本明确指定 UTF-8；时间统一使用 UTC ISO-8601 存储。
- SQL 使用参数化查询；HTML、Markdown、URL 中的用户/数据源字段在输出边界转义。
- 不在业务代码中写死密码、令牌、个人信息或机器绝对路径；配置由环境变量或受控配置文件注入。

## 3. AI/RAG 代码规范

- 检索器、重排器、缓存和路由器应有清晰接口；UI 不直接操作向量库或模型。
- 每次回答保留来源 ID/标题、检索配置版本和必要耗时；无法确认时返回人工转接，不猜测。
- 检索内容一律视为不可信数据，不得执行其中的指令；新增 Prompt 必须经过注入测试。
- 模型、嵌入、分词器变更要记录版本、许可、资源需求和回滚方案；不要把预期指标写成实测指标。
- 新检索策略默认通过配置开关关闭或保留旧策略；失败时回退到当前基线。

## 4. 错误处理与日志

- 面向用户返回稳定、可操作的中文提示；详细堆栈只写受控日志。
- 捕获异常时保留原始异常作为链式原因，避免 `except Exception: pass`。
- 日志不得记录密码、令牌、完整身份证/手机号、完整对话或模型提示；生产日志需脱敏。
- 关键操作带关联 ID（会话 ID/请求 ID）；记录阶段、耗时、结果状态和降级原因。
- 外部依赖（Ollama、模型下载、索引、SQLite）必须有超时、失败提示和可回滚路径。

## 5. 测试规范

测试分层：

| 层级 | 内容 | 最低要求 |
|---|---|---|
| 单元测试 | 校验器、数据转换、RRF/过滤/安全规则 | 新增分支和失败路径覆盖 |
| 集成测试 | Chroma/SQLite/Ollama 边界（可用 Mock） | 不依赖公网；固定测试数据 |
| 回归/安全 | `tests/test_security.py` 及注入、SSRF、XSS、限流 | 每次发布前执行 |
| 评估测试 | RAG 来源命中、事实性、无答案和追问 | 评估集版本化，记录结果 |

推荐本地检查（项目当前未强制配置格式化工具，采用团队统一版本后再纳入 CI）：

```powershell
python -m py_compile app.py ai_service.py knowledge_base.py conversation_store.py
python -m unittest discover -s tests -v
python check_environment.py
```

## 6. Definition of Done

- [ ] 需求、非目标和验收标准已更新。
- [ ] 代码、测试、配置和文档同步变更。
- [ ] 正常、空值、依赖不可用、恶意输入和回滚路径已验证。
- [ ] 本地编译/测试/环境诊断有可复现命令和结果。
- [ ] 无凭据、个人敏感数据、临时文件或大模型产物进入提交。
- [ ] PR 完成审阅，发布说明包含影响、风险、监控和回滚方式。
