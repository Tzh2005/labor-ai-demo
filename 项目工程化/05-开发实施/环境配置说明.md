# 环境配置说明

**版本**：v1.0（Windows 本地 MVP）  
**目录**：`labor-ai-demo`  
**原则**：配置与代码分离，凭据不入库，先诊断再启动。

## 1. 支持矩阵

| 项目 | MVP 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 11（开发验证） | Linux 云部署需单独验收 |
| Python | 3.10+，推荐 3.11/3.12 | 与依赖兼容性需锁定 |
| 内存 | 至少 8 GB，推荐 16 GB | BGE/Ollama 会占用内存 |
| 磁盘 | 至少 10 GB 可用 | 模型、索引和缓存 |
| Ollama | 已安装并运行 | 默认端口 `11434` |
| 模型 | `qwen2.5:3b` | 可配置为已安装模型 |
| 浏览器 | 现代浏览器 | 页面默认 `8501` |

## 2. 首次安装

```powershell
cd D:\1-myFiles\Desktop\AI实习\labor-ai-demo
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
ollama pull qwen2.5:3b
```

如 PowerShell 禁止脚本执行，使用当前用户范围策略（需遵循组织安全政策）：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

## 3. 运行时配置

| 变量 | 默认值 | 是否必需 | 说明 |
|---|---|---:|---|
| `DEMO_PASSWORD` | 无 | 是 | 页面访问密码；长度和复杂度由管理员设定，不写入文件 |
| `OLLAMA_MODEL` | `qwen2.5:3b` | 否 | 必须是本机已安装模型 |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | 否 | 代码只允许 loopback 主机 |
| `HF_HUB_OFFLINE` | 未设置 | 否 | 模型已缓存后可设为 `1`，避免联网检查 |
| `NO_PROXY`/`no_proxy` | 系统值 | 否 | 程序会补充本地地址，避免代理转发 Ollama |

当前应用没有自动加载 `.env` 的实现。开发者可以在当前终端设置环境变量，禁止把 `.env` 或密码文件提交仓库。

```powershell
$env:DEMO_PASSWORD = "请替换为高强度随机值"
$env:OLLAMA_MODEL = "qwen2.5:3b"
$env:OLLAMA_BASE_URL = "http://localhost:11434"
# 模型已缓存且希望离线运行时：
# $env:HF_HUB_OFFLINE = "1"
```

## 4. 启动与诊断

先确认 Ollama：

```powershell
ollama serve
ollama list
```

另开终端激活环境并运行诊断：

```powershell
cd D:\1-myFiles\Desktop\AI实习\labor-ai-demo
.\venv\Scripts\Activate.ps1
python check_environment.py
python check_environment.py --build-index
streamlit run app.py
```

浏览器访问 `http://localhost:8501`。端口占用时：

```powershell
streamlit run app.py --server.port 8502
```

诊断返回值为非零时不得直接发布；先处理依赖、数据文件、Ollama、模型、SQLite 或索引问题。首次构建嵌入模型需要网络和磁盘，构建成功后才适合离线演示。

## 5. 环境分层

| 环境 | 数据 | 模型/服务 | 凭据 | 发布规则 |
|---|---|---|---|---|
| local | 脱敏演示数据 | 本机 Ollama | 开发者临时环境变量 | 可自由重建索引 |
| test/preview | 固定评估集 | 隔离 Ollama/测试模型 | CI Secret | 禁止真实个人数据 |
| production（待开发） | 业务审批后的真实数据 | 受控模型服务 | 密钥管理器 | 需安全、备份、监控和回滚验收 |

不要把本地 `data/labor_ai.db`、真实岗位数据、`chroma_db/` 或模型缓存复制到测试/生产；使用版本化、脱敏、可重建的输入。

## 6. 目录与产物策略

应纳入版本控制：源代码、`requirements.txt`、脱敏 `data/jobs.json`/`data/faq.md`、测试、工程文档和 `.streamlit/config.toml`。  
不应纳入版本控制：`venv/`、`__pycache__/`、`chroma_db/`（可重建时除外）、SQLite 数据库/WAL、模型缓存、日志、密钥、个人导出文件。

更新岗位/FAQ 后，运行 `python check_environment.py --build-index`，确认 `.data_signature` 更新且查询回归通过。索引重建失败时保留旧索引，不要手动覆盖目录。

## 7. 故障排查顺序

1. `python --version`、虚拟环境和依赖导入。
2. `ollama list` 与 `curl http://localhost:11434`/浏览器访问。
3. `OLLAMA_MODEL` 是否与已安装模型完全一致。
4. `DEMO_PASSWORD` 是否在启动同一终端设置。
5. `data/jobs.json`、`data/faq.md` 是否存在且格式有效。
6. 磁盘、嵌入缓存、`chroma_db/.data_signature` 和 SQLite 文件权限。
7. 查看应用日志；对外只展示通用错误，不复制堆栈和凭据。
