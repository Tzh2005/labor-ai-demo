# 测试策略

## 1. 测试层级

| 层级 | 目标 | 当前工具/方式 |
|---|---|---|
| 静态检查 | 语法、依赖、敏感文件 | `py_compile`、`pip check`、人工检查 |
| 单元测试 | 输入校验、安全过滤、存储边界 | `unittest`，当前 `tests/test_security.py` |
| 组件测试 | 知识库建索引、检索、会话存储 | 临时目录 + Mock/小数据 |
| 端到端测试 | 认证、问答、岗位筛选 | Streamlit 手工验收或浏览器自动化 |
| RAG评估 | 召回、事实性、相关性 | `RAG评估集.json` + 评估脚本 |
| 发布验证 | 环境、回滚、备份、日志 | `07-发布上线`、`08-部署运维`清单 |

## 2. 必测风险

- 空输入、超长输入和频率限制。
- Ollama未启动、模型未安装、索引缺失或损坏。
- 恶意检索文档和恶意模型输出。
- 岗位字段缺失、数据类型错误、重复岗位。
- SQLite并发写入和数据库目录不可写。
- 手机窄屏、按钮文字对比度和键盘焦点。

## 3. 回归用例矩阵

| ID | 场景 | 期望 | 证据 |
|---|---|---|---|
| T-01 | 查询“石岩普工” | 返回岗位来源，不编造字段 | 自动/评估集 |
| T-02 | 追问“工资多少” | 使用上一轮上下文或澄清 | 手工/端到端 |
| T-03 | 地区+岗位双筛选 | 结果同时满足两个条件 | 端到端 |
| T-04 | 模型不可用 | 显示可操作状态，不泄露堆栈 | 手工 |
| T-05 | 恶意上下文 | 被过滤并转人工 | `test_security.py` |
| T-06 | 数据签名未变 | 复用索引 | 组件测试 |
| T-07 | 数据签名变化 | 重建索引且失败不破坏旧索引 | 组件测试 |
| T-08 | 清空会话 | 只保留欢迎消息 | 端到端 |
| T-09 | 无来源问题 | 明确需要人工确认 | 端到端 |
| T-10 | 移动端宽度 | 无横向溢出，控件可操作 | 截图验收 |

## 4. 测试数据规则

- 使用脱敏或模拟数据；真实身份证、电话、住址不得进入仓库。
- 评估集中的期望答案写“事实要点”，不要写依赖模型措辞的长文本。
- 每次岗位数据变更都要重新执行数据校验和关键评估题。

## 5. 质量报告

每次发布记录：测试版本、数据签名、模型名、通过/失败用例、首字延迟、全文延迟、无来源回答数和已知风险。
