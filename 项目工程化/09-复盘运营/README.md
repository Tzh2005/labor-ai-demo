# 09｜复盘运营

本目录把发布后的技术信号、用户反馈和业务结果闭环起来。第一版只定义可落地的指标和记录方式，不把尚未接入埋点或尚未验证的数字写成事实。

## 文件地图

| 文件 | 用途 |
|---|---|
| `复盘模板.md` | 发布复盘、事故复盘和迭代复盘的统一模板 |
| `发布复盘模板.md` | 单次版本发布的轻量记录表 |
| `用户反馈闭环.md` | 反馈分级、字段和处理状态 |
| `运营指标定义.md` | 现有指标的简表定义 |
| `运营指标与数据闭环.md` | 指标定义、数据来源、看板节奏和行动规则 |

## 复盘触发条件

- 每次正式发布结束后 1 个工作日内完成轻量发布复盘。
- P0/P1 事故在恢复后 24 小时内启动专项复盘；P2 按影响决定。
- 需求迭代结束、用户反馈出现共性问题、模型/检索策略重大变化时，补充产品复盘。

## 复盘原则

1. 先还原事实和时间线，再讨论原因；不以个人失误替代系统性原因。
2. 区分“已测量”“抽样估计”“待补数据”，不夸大结论。
3. 每项改进必须有负责人、截止日期、验收标准和优先级。
4. 运营数据按最小必要原则使用，优先聚合，不传播完整聊天正文和个人信息。
